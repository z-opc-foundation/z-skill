## 1. 两支等价变异：守卫写在那儿，摘掉却不会红

`HttpFetcher.Jdk` 这层本轮第一次被真 socket 覆盖到（`HttpFetcherJdkLiveTest`，11 条），
注入自证时发现两条"绿得没有意义"的：

**(a) 状态码判定对 500 是等价的。**
`z-skill-core/src/main/java/com/zifang/z/skill/core/discover/HttpFetcher.java:39` 那句
`if (code < 200 || code >= 300) throw new IOException(...)` 摘掉之后，"500 要失败"那条用例**仍然绿** ——
`HttpURLConnection.getInputStream()` 自己对 5xx 抛
`Server returned HTTP response code: 500 for URL: …`，异常类型与消息都满足断言。
这条判定真正的猎物是**跨协议 307**：摘掉之后 `unfollowedRedirectFailsInsteadOfHandingOverTheRedirectPage` 红在
`实际拿到 42 字节: <html>307 Temporary Redirect, 这不是索引</html>`（跳转页被当成索引交给了归一器）。
⇒ 结论：**这一句该留**（它给的是自家消息，比 JDK 那句可读，且 307 那一档只有它拦得住），
但**任何文档都不许写"摘掉状态码判定会被测出来"** —— 500 那一半是假账。

**(b) "UTF-8 改成平台默认字符集"在本机等价。**
`new String(bytes, StandardCharsets.UTF_8)` 换成 `new String(bytes)` 全绿，因为这台 JVM
`file.encoding=UTF-8`、`Charset.defaultCharset()=UTF-8`（实测两条读数相同）。
⇒ 中文那条断言目前钉的是"这台机器上取到 UTF-8"，**没有钉住"显式按 UTF-8"**。
要钉住就得把 surefire fork 的 `-Dfile.encoding` 压成非 UTF-8（JDK 8 的 `argLine` 要写字面值，CLI `-DargLine` 覆盖不了子 pom），
或者换一层量具。**排产建议**：优先级不高（本仓所有部署目标都是 UTF-8 默认），但不许当成已覆盖。

```bash
cp 该文件到备份 → 改 → mvn -o -pl z-skill-core -am -Dtest=HttpFetcherJdkLiveTest -Dsurefire.failIfNoSpecifiedTests=false test
# 判定只认 surefire XML 里具名用例的 <failure>；构建非零不等于测到了

```

⚠ 一条自己踩到的记录法问题：本轮我在过程记录里给这个文件写过另一个 md5，现在**复算不出那一串**。
盘上内容与 HEAD 一致、`git status` 干净、守卫行在位、11 条全绿 ⇒ 判定是"树没坏、是我抄的那串不作数"。
⇒ 教训：**写进文档的哈希必须当场从命令输出复制**，隔几分钟复算一次；凭记忆/复述的哈希比没有更糟。
