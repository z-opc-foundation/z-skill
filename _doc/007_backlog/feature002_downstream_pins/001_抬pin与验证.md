## 3. 为什么这一杠不能只改数字（这些结论仍然成立，是给动手的人的雷区清单）

0.2.0 相对 0.1.2 **不是 drop-in**，实测到的破坏面有两条（都是"删了 public 类型"级别）：

```
$ git show --stat HEAD~1 | grep -E "delete|loader"
 delete mode 100644 z-skill-core/src/main/java/com/zifang/z/skill/core/loader/SkillLoader.java
```

- `SkillLoader` 整类删除，文件系统扫描并入 `discover/`（`FilesystemScanner` + `PlatformPresets`）。
- `SkillDto` / `SkillInstallDto` 加字段（`installRef`、`resources`、`aliases`、`contentHash` 等），
  公共面一律抹本机绝对路径 ⇒ 依赖旧字段值的消费方读数会变（`installRef` 在公共面上现在是 `null`，见 README §6）。

但**下游有没有引用被删的那个类**，实测是"没有"：

```
$ grep -rn "SkillLoader" --include="*.java" z-boot z-opc | grep -v "/target/"
```

⇒ 命中的是 z-agent **自己的同名类**（`com.zifang.z.agent.engine.agent.skill.SkillLoader`，读 JSON 的那套），
与 z-skill 的 `com.zifang.z.skill.core.loader.SkillLoader` 无关。**别照类名归因**，归因要看包名 + pom 坐标。

`z-boot-skill-starter` 只依赖 `z-skill-starter`、**不带 `z-skill-admin`** ⇒ 走聚合 starter 的宿主没有控制台。
这不是漏配：本仓 README §6 写明控制面要 `z.skill.enabled=true` **且** `z.skill.expose-admin=true`
并把 `z-skill-admin` 显式加进 classpath。⇒ 抬 pin 时**不要**顺手把 admin 塞进聚合 starter。

`mvn -B verify -DskipTests`（日志 `~/.cache/zopc-zboot-pin/verify2.log`）
⇒ **同机同树再起一个 reactor 就是"全量测试必须串行"那一类互造假红**，本轮不跑。

### 不跑构建也能拿到的两条证据（先记下，省得下轮以为什么都还没验）

1. **下游对 z-skill 没有编译期耦合**：`z-middleware-integration-test` 里 `com.zifang.z.skill` 只出现 2 行，
   且都是**字符串字面量**（`tryLoad("com.zifang.z.skill.starter.autoconfig.ZSkillAutoConfiguration")` + 对它的一次 `isEqualTo`）
   ⇒ 0.2.0 删掉 `SkillLoader` 之类的 public 类型**打不断它的编译**。

   且这个 jar 与发布件 sha256 整件相等（见 `../../发布到Central/001_0.2.0发布与对账.md` §7）
   ⇒ 抬 pin 后这条探针不会因"类没了"而红。
